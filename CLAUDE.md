# CLAUDE.md — Institutional Equity Research System

A Claude Code multi-agent system for buy-side equity research, run like a fund for one owner's capital: one CIO (the main session), eleven specialist subagents (ten before methodology 3.2.0), an independent auditor, the workers that acquire and read the documents (`librarian`, `reader`, `critical-reader`, `historian`, `digest`), `triage` for the funnel, and the synthesis pipeline that builds the final report from all of the evidence (`theme-analyst`, `layer-analyst`, `section-writer`). The goal is better investment decisions and per-share, risk-adjusted compounding. It is not about producing long reports. Methodology 4.0.0 (`docs/FRAMEWORK_CHANGES.md`) is built on branch `v4.0` and released only after its release gate (`scripts/release_gate.py`) and the first live run.

## Run research
- `/research-company "<Company name>" <TICKER> <EXCHANGE> [--profile lean|standard|deep|max] [--set name=value] [--cutoff YYYY-MM-DD] [--reading on|off]`: this session becomes the CIO and follows `.claude/agents/cio.md`; from 4.0.0 `python3 scripts/orchestrate.py next RUN_DIR` says what comes next (from the run's files alone) and names the stage skill to load, and `orchestrate.py run` runs every script and engine step itself. **Depth is a dial:** the switches and presets are in `config/switches.json` (`docs/SWITCHES.md`, `/switches`); no switch caps a verdict or a confidence, and every report ends with a Depth Disclosure and the command to go deeper (`new_run.py --deepen RUN_ID`, `/deepen`). Start the session on **Opus at xhigh**: models and efforts are pinned per agent in `methodology/MODEL_POLICY.md` (the CIO, specialists, auditor and synthesis roles on Opus at xhigh; in the reading stage Opus at high reads every chunk, with a Sonnet or Haiku second read; librarian, historian and digest on Sonnet at high; `--effort max` for a run).
- Modes: `--validate-only [--probe]` (no research), `--dry-run "<Name>" <T> <EX>` (writes nothing), `--resume <T> <RUN_ID>`.
- **Around the runs (4.0.0):** the warehouse (`scripts/warehouse.py`: point-in-time prices and reported facts, and finished runs' verified facts, never conclusions; agents never read it, a run gets `corpus/facts/` as of its cutoff); the funnel (`/scan`, `/triage`, `/refresh`, `/deepen`); the owner's own decision (`/decide`, apart from the verdict), `/rank`, `/ic`, `/postmortem`, `/run-status`. **Jurisdictions:** a run's jurisdiction follows from its exchange (`config/jurisdictions/IN.json`, `US.json`); a US run uses `scripts/edgar.py` for filings, facts, prices and the Treasury rate, and its specialists are told what the methodology's Indian words mean there.
- **The guard** (`scripts/guard.py`, a PreToolUse hook in `.claude/settings.json`): a finished run, an assembled `cio/final_report.md`, `archive/`, the scoreboard and `latest_run.txt` are never hand-edited. When it denies a call, use the route it names (a new run, `synthesis.py assemble`, `finalize_run.py`); never work around it.
- Stage 3 (since 3.2.0) is the **synthesis pipeline** (`methodology/SYNTHESIS.md`, `scripts/synthesis.py`, `agent_driver.py synthesis --step registry|themes|layers|writers`): an evidence registry of every finding, claim, conflict and reading or digest item → theme analysts that give every item a disposition → the CIO's contradiction log and follow-ups → four independent layer analysts → the CIO's decision from a bounded packet → section writers → `synthesis.py assemble` (the report is a build artifact of `cio/sections/` and `synthesis/sections/`) → `synthesis.py integration`, checked by `validate_run.py --stage final` and the auditor's Evidence Integration Audit.
- Never spawn a `cio` subagent. Every other agent runs as its own headless session through the engine `scripts/agent_driver.py` (isolated from user-level hooks, plugins and memory, checked by the reading audit; pinned model and effort, one-hour cache, usage limits waited out, long agents handed to a fresh session at 250k context after a checkpoint; the Agent tool only when no `claude` binary is found). The specialists are **independent heads**: none can read another's work, `synthesis/`, `cio/`, `audit/` or other runs, and the reading audit checks it. They run **one at a time by default** (`--parallel` optional): `financials`, `filings`, `industry`, `scuttlebutt`, `moat`, `management`, `concalls`, `forecasting` (since 3.2.0: driver model, consensus, surprises, peer table; `scripts/forecast_tools.py`), `valuation`, `special-situations`, `bear-case`, all from one brief (`templates/specialist_prompt.md`), each with the **sector-module** steps the run selected (`methodology/SECTOR_PLAYBOOKS.md`, SECTOR_MODULES block; manifest `sector_modules`; since 3.2.0). Each specialist's work is **verified** the moment it passes its validator (`scripts/verify.py`: values never seen in a source, sources and pages never opened, pack not read; then the `verifier` agent re-opens a sample of its claims at the sources) and every finding goes back to it; `verify.py run` gates Stages 2 and 4, and lessons from earlier runs' verification go into the next briefs. The `auditor` runs once the draft is complete (Stage 4) and writes only under `RUN_DIR/audit/`.
- Stage 0 acquires the filings once for the whole run: `scripts/exchange_index.py` (NSE, BSE, IR site, Internet Archive) → `scripts/document_map.py` (download, validate, cross-check against the FilingForge corpus) → `corpus/DOCUMENT_MAP.md`; the `librarian` finds what the indexes missed; the `historian` (`agent_driver.py events`) builds a sourced ten-year timeline of major events from news and the web, which the reading is checked against; `scripts/structured_filings.py` fetches the exact exchange filings (BRSR XBRL, voting results, audit-opinion statements).
- **Reading mode** (since 3.2.0; manifest `reading_mode`, set by `new_run.py --reading on|off`, default **off**; runs without the field are on). The reading framework below is intact and switched on per run; switching after Stage 1 is refused. **Off:** Stage 0c, the `digest` agent (`agent_driver.py digest`), records what web summaries say about each annual report, transcript and presentation as tier-6 leads; `scripts/digest.py confirm` page-confirms each number against the downloaded filings, `digest.py build` gives every specialist a pack, and `verify.py` blocks a FACT that cites a digest item (`DIGEST_AS_FACT`).
- **On:** Stage 0b reads every in-scope page once and records it (every page of the latest 5 fiscal years' annual reports, the core sections of the 5 before; a missing in-scope report blocks the plan until found or explained): `scripts/reading.py plan` → `scripts/agent_driver.py reading` runs the `reader` / `critical-reader` launches as headless sessions outside the CIO's context, one at a time by default (critical sections read by both, independently; disagreements resolved against the page) → `reading.py dossiers` (topic dossiers and one reading pack per specialist) → `reading.py status --strict` (`corpus/reading/COVERAGE.md`, the only statement of what was read). A document an earlier run read and audited is reused. `scripts/reading_audit.py` checks it from the agents' transcripts at Stage 4.

## Where things live (read the relevant file; do not rely on memory)
- `.claude/skills/investment-constitution/SKILL.md`: **canonical** four layers, fit scale, epistemic tags, citation syntax, specialist protocol
- `methodology/`: `SCORING.md` · `EVIDENCE_STANDARDS.md` · `REPORT_CONTRACTS.md` · `RESEARCH_PLAYBOOK.md` (how to research; **≥10-year depth standard**; §1c the reading stage; §1d the web digest) · `READING_SCHEMAS.md` (what readers extract) · `SYNTHESIS.md` (the final-report pipeline) · `MODEL_POLICY.md` (which model and effort does which work) · `METRIC_DEFINITIONS.md` · `SECTOR_PLAYBOOKS.md` · `SOURCE_GUIDE.md` · `INVESTOR_LENSES.md`
- `config/investment_policy.json`: owner policy. **No position or risk limits**; hurdle = the run's cited cost of equity. Nothing in it limits research depth.
- `config/data_sources.json` → FilingForge library (`~/Documents/FilingForgeLibrary`): read the company's filings there via `scripts/corpus.py` (Markdown, token-efficient) **and** the exchange / IR originals (document map) **and** full web research, at par. The library may be incomplete or have download glitches, so it never limits research (`methodology/SOURCE_GUIDE.md` §0).
- `MASTER_RESEARCH_FRAMEWORK.md`: what to investigate. `PROJECT_INSTRUCTIONS.md`: global rules
- `research/companies/<TICKER>/runs/<UTC RUN_ID>/`: one directory per run; `latest_run.txt` points to the latest complete run. `COMPANY_SCOREBOARD.csv`: compact index (the two scores, and from 4.0.0 preset, verdict, layer, sector, confidence and E[IRR]). `research/outcomes/`, `research/funnel/`, `research/warehouse/` (gitignored)
- `archive/`: old Antigravity definitions, **non-operative**. `docs/`: audit, architecture, operations

## Non-negotiables
1. The four layer names are immutable: Layer 1 — Bedrock Compounder; Layer 2 — High-Growth Business; Layer 3 — Cyclical / Event-Driven Opportunity; Layer 4 — Venture-Style / Optionality Bet. Analyze all four before classifying. SME listing does not set the layer.
2. Business Quality, Investment Attractiveness and layer fit are three separate measures. Score only per `methodology/SCORING.md`.
3. Never invent sources, URLs, pages, figures, quotations, agent outputs or check results. Never state reading coverage that the reading ledger does not record. Material claims carry tags and claim IDs from a ledger, and quantitative claims carry a metric key. Material arithmetic comes from the scripts, not mental math.
4. Only the CIO updates the scoreboard (via `scripts/finalize_run.py`) and runs git (via `scripts/git_publish.py`: two serialized batches, push to the current branch, never force, never auto-merge). Never stage unrelated files (for example the untracked `research/companies/BAJFINANCE/`).
5. Never overwrite a previous run; never edit legacy runs or `archive/`.
6. From methodology 4.0.0 no rule decides or caps the verdict: it is the CIO's reasoned judgment from all the research (for, against, the judgment), with the computed guide shown beside it and every departure explained (`methodology/SCORING.md` §0). Rules about whether the research is true stay strict (3 above). The owner's own decision stands apart (`decide.py`).
